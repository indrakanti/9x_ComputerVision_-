# Real-Video Tracking Benchmark (A5 / PR #32)\n\nThis extension moves the A4 tracker comparison from a deterministic synthetic sequence to a real captured video with frame-by-frame object annotations.\n\n## Benchmark contract\n\nThe C++ executable accepts:\n\n~~~text\n--video <path>\n--ground-truth <csv>\n--max-frames <N>\n~~~\n\nGround truth format:\n\n~~~csv\nframe,x,y,w,h\n0,120.0,80.0,64.0,48.0\n1,122.0,81.0,64.0,48.0\n~~~\n\nRequirements: one object, one box per annotated frame, zero-based video frame indices, contiguous annotation frames, pixel coordinates, top-left x/y, positive w/h.\n\n## Reproducible real sample\n\nRun:\n\n~~~bash\npython3 12_Tracking/04_MOSSECorrelation/tools/prepare_supervisely_sample.py \\\n  --output-dir build/real_tracking_sample\n~~~\n\nThe helper downloads the upstream Supervisely Oriented Bounding Box Video Sample Annotated release v1.0.0.\n\nUpstream project:\nhttps://github.com/supervisely-ecosystem/oriented-bbox-video-sample-annotated\n\nPinned archive:\nhttps://github.com/supervisely-ecosystem/oriented-bbox-video-sample-annotated/releases/download/v1.0.0/project.zip\n\nThe preparation script downloads and extracts the versioned archive, discovers its video/annotation JSON, selects the object with the longest contiguous annotation run unless --object-key is supplied, converts oriented rectangles to axis-aligned evaluation boxes, and writes ground_truth.csv plus provenance.txt.\n\nThe external video is not committed or redistributed in this repository.\n\n### Rights / attribution note\n\nThe upstream repository describes and distributes the sample but does not expose an explicit LICENSE file in the repository metadata used for this lesson. This repository therefore treats the video only as an external evaluation dependency. Review upstream source terms before redistribution or publication. For paper-quality evaluation, prefer a benchmark with explicit terms appropriate to the publication.\n\n## Run\n\n~~~bash\ncmake -S . -B build -DCMAKE_BUILD_TYPE=Release\ncmake --build build --target cv9x_mosse_correlation\n\npython3 12_Tracking/04_MOSSECorrelation/tools/prepare_supervisely_sample.py \\\n  --output-dir build/real_tracking_sample\n\n./build/cv9x_mosse_correlation \\\n  --video <video-path> \\\n  --ground-truth build/real_tracking_sample/ground_truth.csv \\\n  --output-dir build/real_tracking_sample/results\n~~~\n\nOptional limit:\n\n~~~bash\n./build/cv9x_mosse_correlation \\\n  --video <video-path> \\\n  --ground-truth build/real_tracking_sample/ground_truth.csv \\\n  --max-frames 300 \\\n  --output-dir build/real_tracking_sample/results\n~~~\n\n## Outputs\n\n~~~text\ntracker_frames.csv\ntracker_summary.csv\ntracker_comparison_last_frame.png\nsuccess_plot.png\nprecision_plot.png\n~~~\n\nSuccess sweeps IoU threshold from 0 to 1. Precision sweeps center-error threshold from 0 to 50 pixels. The summary retains precision@20px.\n\n## Evaluation policy\n\nWhen OpenCV tracking is available, MOSSE, KCF, and CSRT receive the same first-frame box and run open-loop. Ground truth is used only for evaluation and never for reinitialization. Without the optional tracking module, the real-video benchmark still runs MOSSE.\n\n## CI policy\n\nCI does not download the external real-video asset. The deterministic synthetic self-test remains the regression gate because it is small, offline, reproducible, and stable against upstream hosting changes. Real-video evaluation is a benchmark step, not a unit test.\n\n## Runtime interpretation\n\nmean_latency_ms measures tracker update calls only. Cross-machine comparisons require recording CPU, compiler/optimization, OpenCV version/build flags, threading, power mode, and image resolution.\n\n## Extension ideas\n\n- multiple real sequences with an evaluation manifest\n- published SHA-256 checksums when upstream release bytes are guaranteed stable\n- target-size-normalized center precision\n- success-plot AUC\n- failure/recovery metrics\n- scale-change and occlusion tags\n- JSON summary for dashboards\n
